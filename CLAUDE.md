# Remixer — UI/UX проект (DreamHost AI Website Builder)

## Кто с тобой работает и что это за проект

Пользователь — **UI/UX дизайнер в DreamHost** (Roman). Он рисует интерфейс Remixer —
AI-билдера сайтов от DreamHost. **Он не программист**: не знает код, git, GitHub —
вся техническая сторона полностью на Claude. Объясняй технические вещи просто,
никогда не проси его выполнять команды или разбираться в коде.

Это **проект на годы**. Работа идёт постоянно, сессиями. Всё ценное — знания,
исследования, решения, код — обязано попадать в этот репозиторий
(`romanpotochevsky-design/Remixer`), потому что контейнер сессии умирает, а репозиторий
— нет. Правило: закончил осмысленный кусок работы → закоммить и запушь. Новое знание
о конкурентах или продукте → допиши в базу знаний в `docs/` и обнови этот файл, если
изменилось что-то фундаментальное.

## Прототип (`prototype/`)

React 18 + Vite + TypeScript + Tailwind + zustand + motion. Запуск: `npm install && npm run dev`.

Архитектура (не ломать, расширять):
- `src/state/world.ts` — **единственный источник правды**. Все экраны рендерятся из одного
  объекта World: account × inventory (что за домены у юзера) × domain state × project × chat.
  Новое измерение состояния сначала добавляется сюда.
- `src/state/flows.ts` — декларативный движок флоу: сценарий проигрывается целиком от начала
  до конца («что происходит, когда я подключаю домен с GoDaddy») — для демо CEO.
  Шаги с реальным решением ставят `awaitUser`; ожидания сжаты, но пропорциональны.
- `src/state/scenarios.ts` + `src/devtools/ScenarioPanel.tsx` — консоль сценариев (мировых состояний).
- `src/i18n.ts` — EN по умолчанию (продукт для рынка США), UK вторым.
- Геометрия шелла — **редизайн 2026** из Figma (узел 25819:143144 «Website Builder»,
  снято 16.08.2026): чат СЛЕВА 432px, топбары 52px, рейл СПРАВА 56px (аватар + Style/
  Extension/Analytics/Cloud 48px + freshchat), фон #09090b, «стеклянные» контролы
  (rgba(24,24,27,.8) + blur 16 + белый 15% бордер), панель Publish 548px радиус 20.
  Старая геометрия живого продукта (57/64/522) устарела — не откатывать.
- `src/ui/icons.tsx` — иконки перерисованы вручную (SVG-экспорт Figma блокирует прокси).
- `src/ui/SiriGlow.tsx` + секция «Siri edge glow» в `index.css` — фирменный «Remixer glow»:
  свечение по кромке превью во время процессов (генерация/агент/перезагрузка). Сведён
  с реальным эффектом Siri по стоп-кадрам и фото устройств. **Перформанс-контракт:
  ни одно свойство не инвалидирует paint покадрово** — только transform/opacity
  (наивная версия давала 9 FPS). Встроенный «губернатор качества»: телефоны и слабые
  машины автоматически получают лёгкий срез. Спецификация для девелоперов:
  `docs/handoff/siri-glow-spec.md`.
  ⚠️ Урок: Tailwind вычищает классы, собранные динамически (`siri-layer--${k}`) —
  имена классов в tsx всегда писать полными литералами.
  ⚠️ **Свечение стоит почти весь кадровый бюджет.** Замер на опубликованной сборке
  (браузер без GPU): со свечением страница рисует 4 fps, без него 60. Перенос блюра
  внутрь, «лёгкий» срез и отключение «дыхания» не помогают — дорого само размытие
  больших поверхностей. Поэтому свечение **стартует через 700 мс после отправки**
  (`App.tsx`), иначе оно съедает кадры у пружины пузыря и у печати ответа, и обе
  анимации выглядят как «их нет».
  **Glow — единственный индикатор загрузки превью.** Никакого скелетона, затемнения
  и перемонтирования сайта: страница остаётся видимой, весь сигнал «идёт работа»
  несёт вспышка появления + бегущее свечение (как на реальном устройстве, где эффект
  играет поверх любого контента). Скелетон был — убран осознанно, не возвращать.
  Режимы поверхности: `light` (узкий ободок), `dark` (полное свечение),
  `split` (сайт светлый сверху / тёмный снизу — статичная маска разводит слои по границе).
- **Стекло — по macOS, не по iOS.** База из Figma (`Preview buttons` 25819:143747):
  заливка `rgba(24,24,27,.8)`, `backdrop-blur 16`, дивайдеры внутри групп `#ffffff0a`
  (Neutral Alpha/50). Рамка — **косой градиент**, а не ровная линия: настоящее стекло
  ловит свет неравномерно. Но амплитуда мягкая, вокруг фигмовских 12% (Neutral Alpha/200):
  20% → 7% → 16% по диагонали 150°. Что делало версию «айосной» — это была амплитуда
  (32% белого в горячем конце) плюс внутренняя подсветка сверху, тень и saturate; всего
  этого быть не должно. Рамка рисуется маской по border-box (`::before`), не `border` —
  чтобы не сдвигать лейаут и следовать радиусу.
- **С iOS 26 берём ТОЛЬКО анимации, не материал.** Стекло — там, где оно есть в Figma
  (кнопки-пилюли в тулбарах, пузыри чата). Панель Publish в макете — сплошная `gray-850`,
  и такой и остаётся: полупрозрачное стекло на ней было ошибкой, откатано.
- **Моушен — `src/ui/motion.ts`, один язык на все оверлеи** (взято с iOS 26): пружины
  вместо длительностей; попап растёт из угла своего триггера (`transform-origin`);
  контент приезжает на 60 мс позже контейнера; уход быстрее прихода и без отскока.
  Анимируются только `transform` и `opacity`. Новые меню/дропдауны брать отсюда,
  а не писать свои `duration/ease`.
- В чате две растушёвки, обе sticky и обе **чистый градиент без плоского участка**
  (плоская «голова» читается как обрезанный край): сверху 48px `#09090b`→прозрачный
  (Figma 28016:43309), снизу 32px прозрачный→`#09090b` вплотную над полем (28016:46454).
  ⚠️ У скроллера НЕ должно быть верхнего паддинга: sticky прилипает к padding-краю
  вьюпорта, и любой `pt` оставляет над растушёвкой щель, в которой сообщения проезжают
  открытыми. Растушёвка сама стоит в потоке и заодно служит отступом над первым
  сообщением; снизу колонка резервирует `pb-8`.
  Между чатом и канвасом — `src/ui/ChatResizer.tsx`: в покое hairline `--white-100`
  (Neutral Alpha/100; в макете колонка 432, всё внутри 430–431 — этот пиксель и есть
  линия), за него можно **тянуть** и менять ширину чата (340–760). На драге линия
  становится синей, у курсора — ручка «◁▷», и по линии едет блум, привязанный к
  позиции курсора (у Lovable подсветка ровная — у нас свет там, где рука).
  ⚠️ Драг НЕ идёт через React: ширина пишется прямо в `--chat-w` на `<html>`, блум
  двигается `transform`. Ререндер шелла на каждый pointermove перезапускал бы чат,
  превью и его container queries 60 раз в секунду. В стор значение падает на отпускании.
- **Отправка уводит сообщение НАВЕРХ вьюпорта** (как у Lovable, снято с видео их билдера):
  прочитанный тред уезжает, твой запрос встаёт под шапкой, всё под ним пустое — там
  появится ответ. Чат, липнущий к низу, наоборот выталкивает твоё же сообщение с экрана,
  пока пишется ответ. Для этого в конце списка растёт спейсер (`ChatPanel`), считается
  один раз на отправку, не во время ответа — иначе лейаут прыгает.
  ⚠️ Высоту «сколько контента ниже» мерить по самому списку, НЕ по `vp.scrollHeight`:
  он никогда не меньше вьюпорта, и на коротком треде замер врёт.
  ⚠️ Перед замером спейсер обнуляется — браузер зажимает `scrollTop` под укоротившийся
  диапазон и тред дёргается (234 → 33 → 294). Сохранять и возвращать `scrollTop` в том
  же кадре.
  ⚠️ Прокрутка стартует ЧЕРЕЗ 320 мс после отправки. Одновременно с пружиной пузыря
  анимации отправки просто не видно: глаз следит за уездом всего треда. Сначала пузырь
  прилетает, потом тред уносит его наверх.
  ⚠️ Флаг анимации — по каждому сообщению (`seen` + `fresh` set), не общий: с общим флагом
  каждая отправка перерисовывала старые ответы и весь тред перепечатывался. И «свежесть»
  не должна сбрасываться на следующем рендере, иначе анимированные слова сносит на лету.
  ⚠️ Не оборачивать печатающийся ответ в motion-анимацию opacity: вложенность гасила
  CSS-анимацию слов (весь блок стоял на opacity 0, слова — на currentTime 0).
- **Флеш при отправке** — цветной свет один раз обегает поле ввода (как у Google на
  кнопке «AI Mode»). Движок тот же, что у Siri-glow: конический градиент нарисован
  один раз на большом квадрате и вращается `transform`, кольцевая маска режет его по
  бордеру. Анимировать угол градиента нельзя — это ровно тот путь, что дал 9 FPS.
  Свет — **дуга, а не кольцо**: бо́льшая часть конуса прозрачная, поэтому в каждый
  момент горит один участок периметра и видно, что он едет.
  ⚠️ Chrome НЕ рендерит маску (и `overflow: hidden`) внутри элемента с `filter` —
  проверено по отдельности: каждое само по себе рисует, вложенные гаснут. Маска и блюр
  должны быть на ОДНОМ элементе; плата — маска обрезает разлёт блюра.
  ⚠️ Широкий ореол наружу у нас не помещается: справа от поля 8px до разделителя, а
  сверху всё перекрывает растушёвка чата (`z-index: 10`). У Google поле посреди пустой
  страницы. Поэтому свет идёт по кромке поля, мягко и частично.
- **Композер — по Figma (28016:43526/43528), `.composer-field`:** стекло с базой
  `--glass-bg` (#18181bcc) + 8% белого поверх (`Neutral Alpha/100`), `backdrop-blur 16`,
  рамка `Neutral Alpha/300`
  (белый 24%), радиус 24; кружки «+» и микрофон — `rgba(9,9,11,.64)` + та же рамка 24%
  + blur 16. Общий `liquid-glass` здесь НЕ применять: у него рамка вокруг 12%, поле
  выходит тусклее макета.
  ⚠️ **Токены Figma MCP читать в ТЁМНОЙ теме.** Экспорт резолвит `Neutral Alpha`
  непоследовательно: на кнопках отдал `rgba(255,255,255,.24)`, на поле — светлый
  `rgba(9,9,11,.24)`, и заливку поля показал как «8% чёрного поверх #09090b».
  Буквально это красит поле в цвет фона чата — поверхность исчезает, и стеклу кружков
  не на чем работать. В тёмной теме та же подмешка — 8% БЕЛОГО, и база у поля стеклянная,
  а не чёрная: в макете поле заметно СВЕТЛЕЕ фона, а «+» и микрофон — тёмные диски на нём.
  Кнопка отправки в покое контурная, без заливки (28016:43545), синей становится только
  когда есть что отправить.
- Индикатор ожидания — «Thinking» с бегущим по буквам бликом (`.thinking`,
  `background-clip: text`). Это единственное место, где repaint покадрово допустим:
  одно короткое слово, живущее только пока пишется ответ.
- Моушен чата: своё сообщение выпрыгивает из композера как в iMessage (`bubbleSend`,
  origin bottom-right, пружина `bounce .34 / duration .5`), ответ Remixer «печатается» —
  все слова свёрстаны сразу, но проявляются со ступенькой (`.stream-word`, шаг сжимается
  на длинных ответах, весь ответ ≤ ~1.1 с), кнопки под ответом ждут конца печати.
  ⚠️ Без blur на словах: blur-in красивее, но перерисовывает текст каждый кадр, а в полёте
  одновременно ~15 слов — это ровно тот per-frame paint, который запрещён после 9 FPS.
  Анимируются только сообщения, пришедшие ПОСЛЕ первого рендера (`settled` ref),
  иначе весь тред «выпрыгивает» при каждой загрузке страницы.
- Чат живой: `modules/chat/send.ts` — одно сообщение двигает весь шелл (пузырь → `chat:
  'working'` → glow на превью → через 2.6 с захардкоженный ответ → −10 кредитов →
  +1 к unpublished). Ответы подбираются по ключевым словам в `modules/chat/thread.ts`
  (фото, палитра, мобилка, цены, меню, форма, публикация…), остальное — ротация из трёх
  общих. Транскрипт живёт в `world.sent`; первое отправленное сообщение «замораживает»
  демо-тред сценария внутрь этого массива, дальше `chat` работает только как статус.
  Смена оси `chat` (переключение сценария) обнуляет `sent`.
- Переключатель девайсов — **одна кнопка**, как у Lovable (проверено по видеозаписи их
  билдера): иконка = текущий режим (монитор → после клика телефон), клик переключает.
  Мобильный режим — **фиксированная рамка 390×844** (iPhone 14/15), центрированная по
  обеим осям: сверху и снизу остаётся подложка канваса, а не колонка во всю высоту.
  Glow и скролл идут по рамке телефона. Сайт внутри перестраивается по-настоящему, потому что отвечает
  на **container queries**, а не на ширину окна (у Lovable это даёт iframe; у нас — контейнер
  `.site-stage`). Респонсив-размеры сайта живут в CSS (`.site-pad`, `.site-grid`,
  `.site-hero-title`…), а не в Tailwind-утилитах: утилиты лежат в более позднем слое и
  перебивают правила `@container`. В мобильном режиме у рамки hairline — иначе тёмная
  половина сайта сливается с фоном шелла.
- `src/ui/ScrollArea.tsx` — **все скроллящиеся поверхности только через этот компонент.**
  Нативные скроллбары выключены глобально: классический скроллбар забирает колонку в
  лейауте и красит её фоном скроллера — на двухтонном сайте это давало белую полосу
  вдоль всего правого края, включая тёмную половину. Наш индикатор плавает ПОВЕРХ
  контента: 4px, невидим в покое, появляется при скролле и гаснет через 700 мс,
  per-frame только `transform` (высота пишется лишь при смене размеров).

## Выводы аудита, которые надо держать в голове при каждом дизайн-решении

1. **Публикация должна стоить 0 кредитов.** Мы единственные в категории, кто берёт кредиты
   за публикацию (кроме Emergent с рейтингом 2.7/5). Самая атакуемая строка любой сравнительной таблицы.
2. **Владеть 60 секундами вокруг go-live**, а не «продажей домена» (это теперь у всех):
   zero-record connect для доменов уже в аккаунте DreamHost, понятная state-машина со
   словом-действием на каждый сбой.
3. **Словарь глаголов: Add = купить · Connect = подключить своё · Publish/Update = переопубликовать.**
4. **Де-жаргон:** никаких DNS/nameserver/A record/SSL certificate в основных путях.
   «Point domain to us», «secure padlock», канонический чеклист успеха:
   «Domain settings updated · Connected to your site · Security (SSL) on».
5. **Цену показывать до корзины**, renewal-цену не прятать (иначе dark pattern).
6. **Кредиты — постоянно в тулбаре** (GoDaddy вынес на отдельную страницу — их самая
   громкая жалоба).
7. Контраргумент критики: реальный отток — **до** go-live, на качестве генерации
   (мы сами ставим себе 1/5 за anti-generic). Домены/почта — «последняя миля» для тех,
   кто дошёл. Балансировать приоритеты.
