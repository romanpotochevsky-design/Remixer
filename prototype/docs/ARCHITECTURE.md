# Архитектура прототипа Remixer

**Что это.** Инженерная память прототипа в `prototype/`: как он устроен, почему устроен
именно так и что нельзя ломать при расширении. Раньше всё это жило в `CLAUDE.md` и
превратило файл правил в инженерный чейнджлог. Теперь так: `CLAUDE.md` — правила и
указатели, эти четыре файла — знание.

**Кому.** Claude в следующей сессии. Второй адресат — девелопер, который однажды будет
портировать это в продакшен.

**Соседние файлы:**
- `prototype/docs/PERFORMANCE.md` — кадровый бюджет, свечение, губернатор качества.
- `prototype/docs/CHAT.md` — чат: отправка, прокрутка, флеш, резайзер, композер.
- `prototype/docs/FONTS.md` — Gilroy/Proxima Nova, OFL-подмены, ловушки шрифтов.

Знаки **⚠️** — это уроки, каждый из которых стоил живых часов отладки. У каждого сохранена
причина и замеры. Урок, сжатый до вывода, будет повторён заново — поэтому не сокращать.

## 1. Стек и команды

React 18 + Vite + TypeScript + Tailwind 3 + zustand 4 + motion 11. Бэкенда нет вообще:
все данные захардкожены (`src/data/domains.ts`, `src/modules/chat/thread.ts`).

```
cd prototype
npm install
npm run dev        # vite, 127.0.0.1:5273
npm run build      # tsc -b && vite build — ДОЛЖЕН проходить всегда
npm run artifact   # build + scripts/build-artifact.mjs → один самодостаточный HTML
```

Алиас `@` → `prototype/src` (`vite.config.ts`).

Прототип обязан всегда собираться: сломанный прототип нельзя показать CEO.

## 2. Единственный источник правды — `src/state/world.ts`

Все экраны рендерятся из одного объекта `World`. Никто не держит собственную копию «есть
ли у юзера план» — иначе через год будет двадцать расходящихся версий правды.

**Правило расширения: новое измерение состояния сначала добавляется сюда**, потом читается
в экранах.

Оси мира:
- `account` — `anonymous | trial | trial-expired | paid`, плюс `trialDay`, `billing`,
  `credits`, `bonus`.
- `inventory` (ось A) — **что у юзера уже есть**: `none`, `dh-free` (домен лежит в аккаунте
  DreamHost, кейс zero-record go-live), `dh-in-use`, `dh-external-ns`, `external-dc`
  (авторитативный DNS у провайдера с Domain Connect), `external-manual` (Namecheap —
  только ручные записи). Эта ось решает, какой экран подключения вообще достижим, и
  независима от того, что делает домен текущего проекта.
- `domain` (ось B) — что делает домен проекта: `staging | searching | checkout |
  connecting | verifying | live | unreachable | multiple`.
- `project` — `empty | generating | built`; `unpublished` — счётчик правок с последней
  публикации; `chat` — `empty | short | long | working | error`.
- `sent: Message[]` — живой транскрипт чата (см. `CHAT.md`).
- `lang` — `en | uk`.

Три механизма, которые легко случайно сломать:

1. **`violations(world)`** — список комбинаций, которые реальный продукт произвести не
   может (кастомный домен без плана; проект у анонима; кредиты у истёкшего триала;
   `unpublished > 0` в пустом проекте). Консоль сценариев гасит такие варианты и
   показывает причину — чтобы не потратить утро на дизайн состояния, которого не бывает.
2. **URL + localStorage.** `worldToParams` / `paramsToWorld` кодируют мир в короткие ключи
   (`l a t b c z i d p u h`), `syncUrl` пишет и адресную строку, и `localStorage`, — любое
   состояние это шареная ссылка. Оба вызова best-effort в `try/catch`: внутри
   песочницы опубликованного артефакта `history` и `storage` могут быть закрыты, а
   прототип обязан продолжать работать. Транскрипт (`sent`) в URL НЕ едет специально:
   ссылка несёт ситуацию, а не чью-то печать. Исключение — восстановление прерванной
   отправки (`initialWorld`, см. `CHAT.md`).
3. **Смена оси `chat` обнуляет `sent`.** В `set()`: если пришёл патч с `chat` и без `sent`,
   `sent` затирается. Переключение сценария ставит другую ситуацию, и транскрипт, набранный
   в прошлой, — мусор. Композер всегда передаёт оба поля сразу, поэтому его это не касается.

## 3. Навигация отдельно от правды — `src/state/ui.ts`

Второй стор, специально отдельный. `world` — правда продукта («у юзера есть план, его
домен подключается»); `ui` — куда смотрит камера («открыта доменная поверхность, поднят
попап публикации»). Сценарии и флоу переписывают мир и не должны знать, какая панель
случайно открыта. Именно это разделение позволяет обоим расти годами не спутываясь.

**Паттерн «surface».** Surface — это модуль, который рендерится ВМЕСТО превью сайта
внутри того же шелла (у Lovable это раздел «More», и живой Remixer уже так делает).
Каждый будущий модуль (Analytics, Library, Cloud…) — это ещё одна запись в типе `Surface`,
а не новый лейаут.

Здесь же: `domainScreen` (`home | results | own | external | status`), `domainModal`
(`kind` + `domain`), `publishOpen`, `device`, `chatWidth`, `reloading`. Константы:
`CHAT_DEFAULT 432 / CHAT_MIN 340 / CHAT_MAX 760`, `MOBILE_WIDTH 390 / MOBILE_HEIGHT 844`.

`triggerReload(ms = 3200)` держит ОДИН таймер: долбёж по кнопке перезагрузки продлевает
импульс, а не стакает таймеры.

## 4. Флоу-движка больше нет — удалён 20.08.2026

`src/state/flows.ts` и `src/devtools/FlowPlayer.tsx` **удалены по просьбе дизайнера**:
степпер со стрелками, счётчиком шагов и регулятором скорости пересказывал продукт вместо
того, чтобы дать его потрогать, — а клиент встречает интерфейс не так. Раздел «Whole flows»
из консоли убран вместе с ними.

Теперь **каждый флоу проходится руками, по настоящему UI**, а «Situations» (§5) — только
стартовое состояние, которое выбирают перед тем, как начать кликать. Отсюда жёсткое
требование ко всем новым состояниям: **из состояния, в которое можно войти, должен быть
видимый клик наружу и вперёд**. Ожидания продвигает «Refresh status» — один этап за клик
(`connecting → verifying → securing → live`); `securing` этот контрол получил в тот же день:
раньше его двигал только таймер плеера, и без плеера экран стал тупиком.

## 5. Сценарии и консоль — `src/state/scenarios.ts` + `src/devtools/ScenarioPanel.tsx`

Консоль рендерит себя из `AXES`: добавить измерение позже — это одна запись здесь, а не
операция на UI. `PRESETS` — только ярлыки, которые ставят несколько осей сразу; своего
состояния они не держат никогда.

Открывается **⌘.** (Ctrl+. на Windows) или ручкой в правом нижнем углу. «Режим показа»
убирает ручку, чтобы консоль открывалась только с клавиатуры.

Оформлена как *tooling*, а не как Remixer: светлый фон, monospace, никакого брендового
цвета. В шеринге экрана или на скриншоте её никто не должен спутать с продуктом.

## 6. Локализация — `src/i18n.ts`

**EN по умолчанию** (продукт для рынка США), **UK вторым**. Русского в продукте нет нигде —
это только язык, на котором говорят дизайнер и Claude.

Строки пишутся парами `{ en, uk }` инлайн в месте использования, без реестра ключей. Для
прототипа это надёжнее: оба языка стоят рядом, поэтому перевод не может молча пропасть за
ключом, который всё ещё резолвится в что-то устаревшее. `t()` падает на английский, если
перевода нет.

## 8. Иконки — `src/ui/icons.tsx`

Весь набор перерисован вручную под сетку Figma (24px, штрих ~1.7px). Причина техническая:
**экспорт ассетов Figma из этого окружения недостижим — прокси режет запросы**, поэтому
каждый глиф переавторен как inline SVG по скриншотам макета.

Правило: каждая иконка на `currentColor`, чтобы кнопки красили её через CSS, а не через
пропсы. Логотип `LogoRemixer` — настоящая марка, снятая из статического экспорта
maintenance-страницы.

## 9. Скролл — `src/ui/ScrollArea.tsx`

**Все скроллящиеся поверхности только через этот компонент.**

Нативные скроллбары выключены глобально (`* { scrollbar-width: none }` и
`::-webkit-scrollbar { display: none }` в `index.css`). Причина: классический скроллбар
забирает колонку в лейауте и красит её фоном скроллера — на двухтонном демо-сайте это
рисовало белую полосу вдоль всего правого края, включая тёмную половину. Телефоны так не
делают; мы тоже.

Наш индикатор плавает ПОВЕРХ контента: 4px, невидим в покое, появляется при движении
поверхности или на ховере, гаснет через 700 мс после остановки. Per-frame работа — один
композитный `transform`; высота полоски пишется только когда реально меняется скроллящийся
объём (`ResizeObserver`), никогда во время скролла. Ресайз — не скролл, поэтому при ресайзе
полоска не вспыхивает (`sync(false)`).

Тона: `light` (тёмный хром билдера), `dark` (светлые панели), `auto` — трюк iOS: тёмная
полоска со светлым волоском, читается и на белом, и на чёрном; для контента сайта, фона
которого мы не знаем.

**Плата за это:** всё скроллящееся, что НЕ `ScrollArea`, вообще не имеет видимого
индикатора. Это и есть причина, по которой новые скроллящиеся поверхности обязаны идти
через компонент.

`viewportRef` отдаёт скроллпорт наружу — для тех, кто крутит скролл сам (чат парует новое
сообщение у верхней кромки, см. `CHAT.md`).

## 10. Переключатель девайсов и container queries

Переключатель — **одна кнопка**, как у Lovable (проверено по видеозаписи их билдера):
иконка ЕСТЬ текущий режим (монитор, пока канвас десктопный → телефон после клика), клик
переключает. Двух кнопок-табов нет.

Мобильный режим — **фиксированная рамка 390×844** (логический размер iPhone 14/15),
центрированная по обеим осям: сверху и снизу остаётся подложка канваса, а не колонка во
всю высоту (снято с записи экрана Lovable — их телефон плавает в середине канваса с
широкими полями). Свечение и скролл идут по рамке телефона. У рамки в мобильном режиме
hairline `ring-[#ffffff14]` — иначе тёмные секции сайта сливаются с фоном шелла (у Lovable
превью обведено так же, замеренный бордер `#41413D`).

**Сайт внутри перестраивается по-настоящему, потому что отвечает на container queries, а
не на ширину окна.** `.site-stage { container-type: inline-size }`, а респонсив-правила —
`@container (max-width: 900px)` и `(max-width: 640px)`. У Lovable то же самое получается
бесплатно из iframe превью; у нас — без iframe и без вранья про viewport.

⚠️ **Респонсив-размеры сайта живут в CSS (`.site-pad`, `.site-grid`, `.site-hero-title`,
`.site-nav-links`, `.site-cta`, `.site-stats`), а НЕ в Tailwind-утилитах.** Утилиты лежат в
более позднем слое каскада и перебивают правила `@container` — контейнерному запросу тогда
просто нечем выиграть по специфичности. Поэтому всё, что должно реагировать на ширину
сцены, объявляется классом в `index.css`.

## 11. Демо-сайт как стенд — `src/modules/preview/SitePreview.tsx`

Сайт в превью намеренно **двухтонный**: белый хиро сверху, тёмная секция меню и футер
снизу. Это не случайный дизайн сайта, а **инструмент проверки**: на нём сразу видно
поведение glow на обоих фонах (режим `split`, см. `PERFORMANCE.md`) и поведение
скроллбара `auto`.

Второе правило: сгенерированный сайт специально сделан НЕ в дизайн-языке билдера —
он должен выглядеть как сайт клиента, а не как хром Remixer. И он обязан быть: пустая
тёмная панель в любом демо читается как сломанная сборка.

## 12. Материал и моушен

**Стекло — по macOS, не по iOS.** База из Figma (`Preview buttons` 25819:143747): заливка
`rgba(24,24,27,.8)` (`--glass-bg`), `backdrop-blur 16`, дивайдеры внутри групп `#ffffff0a`
(`Neutral Alpha/50`). Рамка — **косой градиент**, а не ровная линия: настоящее стекло ловит
свет неравномерно. Но амплитуда мягкая, вокруг фигмовских 12% (`Neutral Alpha/200`):
`20% → 7% → 16%` по диагонали 150°, так что средняя совпадает со спекой, а стекло несёт
только распределение. Рамка рисуется **маской по border-box** (`.liquid-glass::before`,
`mask-composite: exclude`), не `border` — чтобы не сдвигать лейаут и следовать любому
радиусу.

Что делало раннюю версию «айосной»: амплитуда 32% белого в горячем конце плюс внутренняя
подсветка сверху, тень и `saturate`. Ничего этого быть не должно — рядом с настоящим
материалом это кричит. Тихий вариант `.liquid-glass--subtle` (пузыри чата, большие
панели): заливка-градиент `6% → 2%` и приглушённая рамка, как в Figma.

**С iOS 26 берём ТОЛЬКО анимации, не материал.** Стекло — там, где оно есть в Figma
(кнопки-пилюли в тулбарах, пузыри чата). Панель Publish в макете — сплошная `gray-850`,
и такой и остаётся: полупрозрачное стекло на ней было ошибкой и откатано.

⚠️ **Бегущий блик по кромке панели при открытии (`.glass-sheen`) — тоже откатан**
(17.08.2026, после вопроса дизайнера «зачем этот эффект блика?»). Причина, а не вкус:
блик — это признак СТЕКЛА, свет, скользящий по прозрачной поверхности. Панель Publish
непрозрачная (`gray-850` по Figma), поэтому блик украшал материал, которого у неё нет, — и
именно на той поверхности, где стекло уже пробовали и откатили. От iOS-26 у панели
остаётся только МОУШЕН (пружина из угла триггера, контент на бит позже). Место, где блик
жил, помечено комментарием в `index.css` — не возвращать.

**Моушен — `src/ui/motion.ts`, один язык на все оверлеи.** Четыре правила, снятые с
iOS 26:

1. **Пружины, а не длительности.** Кривая с длительностью идёт одинаковое время независимо
   от пути; пружина оседает. Поэтому панели Apple ощущаются физическими, а 200 мс ease —
   слайдшоу. `SPRING` (stiffness 520 / damping 34 / mass .9), `SPRING_SOFT` (380/36/1) для
   больших поверхностей — они выглядят глупо, двигаясь так же быстро.
2. **Растёт из того, что ты нажал.** Попап масштабируется из угла своего триггера
   (`transform-origin`), чтобы глаз не терял причинную связь между кликом и панелью.
3. **Контент отстаёт от контейнера** на 60 мс (`popoverContent`). Одновременно — это то,
   что заставляет оверлей читаться как подменённую картинку, а не как открывшуюся
   поверхность.
4. **Уход быстрее прихода и без отскока** (`EXIT`, 140 мс, без пружины). Перелёт на выходе
   читается как нерешительность.

Анимируются только `transform` и `opacity` — две вещи, которые композитор делает без
перерисовки. Ничто в этом файле не имеет права анимировать width/height/blur/color
покадрово. Новые меню и дропдауны берутся отсюда, а не пишутся своими `duration/ease`.

Наборы: `popover`/`popoverContent`, `bubbleSend` (см. `CHAT.md`), `messageIn`,
`modalScrim`/`modalSheet` (у центрированного шита нет угла триггера, поэтому правило 2
заменено очень коротким подъёмом, а `scale` стартует ближе к 1 — 600px шит, растущий с
.94, читается как зум, а не как приходящая поверхность), `listSwap`/`listSwapItem`
(конвейер вместо кроссфейда), `surface`.

## 13. Поверхности домена — где они живут и какие уроки на них получены

Пиксельные спеки этих экранов (Figma-узлы, размеры, токены) — в `CLAUDE.md` и
`docs/features/domains/handoff-design.md`. Здесь только инженерная часть.

- `src/modules/domains/DomainsSurface.tsx` — дашборд + `SearchHeader` + `ResultsScreen`.
- `src/modules/domains/DomainModal.tsx` — чек-аут-шит: три борда рисуют ШЕСТЬ состояний
  ОДНОГО шита по двум независимым осям, поэтому это один компонент, а не шесть:
  `connect-existing` (без цены — свой домен ничего не стоит прицепить) / `buy` (первый год
  + честное продление) × «есть план» (узкий шит) / «нет плана» (шит вырастает на плановый
  выбор Yearly/Monthly, CTA становится «Continue to checkout»).

⚠️ **Шит монтируется в самом верху дерева (`App.tsx`), не внутри `<main>`.** Это
**app-модалка**: скрим 70% чёрного в макете накрывает и колонку чата, и правый рейл.
Смонтированный внутри `<main>` он бы затемнял только канвас, а чат остался бы «живым»
поверх скрима.

⚠️ **Стена плана перед всей доменной поверхностью убрана — гейт живёт только в
`DomainModal`.** Раньше юзер без Remixer Build видел вместо дашборда апгрейд-экран. Все
три борда рисуют ТРИАЛЬНОГО юзера, стоящего в ПОЛНОМ дашборде, со шитом поверх: платёж
раскрывается в момент покупки, внутри шита, и доменная идентичность остаётся приколотой
сверху, чтобы не потерять нить. Это же и правило аудита — «цену до корзины», и оно
конкретизирует «владеть 60 секундами вокруг go-live».

⚠️ **Шапка с поиском монтируется ОДИН раз.** `SearchHeader` живёт в `DomainsSurface`
СНАРУЖИ `AnimatePresence`, и состояние поля (`query`) лежит там же. Раньше шапка была
внутри каждого экрана — поиск подменял экран целиком, `<input>` перемонтировался, терял
фокус и каретку, и это читалось как перезагрузка страницы, а не как «пришёл ответ»
(замечание дизайнера 17.08.2026). Сейчас меняются только списки под шапкой:
`listSwap`/`listSwapItem` из `motion.ts` — уходящий контент уезжает ВВЕРХ, приходящий
поднимается снизу со ступенькой по секциям (конвейер, а не кроссфейд), `AnimatePresence
mode="wait"` не даёт двум наборам наложиться в полёте. Проверено: `<input>` после поиска —
тот же DOM-узел, фокус и текст сохраняются.

Побочное следствие: расхождение макетов (у пустого состояния тайтл 40px и белый сабмит 32,
у результатов 32px и тёмно-стеклянный 40) стало **переходом**, а не двумя компонентами —
герой сжимается, как домашняя страница поисковика оседает в выдачу; кнопка одна и та же,
морфится. Тайтл — единственное место, где разрешён переход по `font-size` (одна короткая
строка, то же исключение и по той же причине, что у шиммера «Thinking»). Открытый вопрос
дизайнеру: если он хочет шапку неподвижной — заморозить `compact`.

⚠️ **Градиентная рамка героя Best match — кольцевой маской (`.bestmatch-rim`), НЕ вторым
слоем `background` под полупрозрачной заливкой.** Заливка карточки 10% альфы, поэтому
непрозрачный градиент под ней просвечивает целиком — так и было: вся строка с лейблом
становилась сплошным фиолетовым баром. Рабочая конструкция — `padding: 1px` +
`mask-composite: exclude`, то есть только кольцо. Ось градиента 90°, та же, что у заливки
карточки: рамка на 135° гнала свет по диагонали против заливки и подсвечивала левый нижний
угол, который заливка оставляет тёмным.

## 14. Сборка артефакта и CSP

`npm run artifact` → `scripts/build-artifact.mjs` складывает Vite-сборку в ОДИН
самодостаточный HTML.

Причина, по которой это отдельный скрипт: **опубликованная страница артефакта работает под
строгим CSP, который режет ЛЮБОЙ внешний запрос.** Ничто не может остаться URL-ом — CSS,
JS и каждый `.woff2` обязаны ехать внутри файла текстом или `data:`-URI.

Что делает скрипт:
1. Инлайнит CSS и JS.
2. Зашивает в base64 шрифты, которые собрал Vite (OFL-подмены из `src/fonts/` — они
   всегда на месте).
3. Зашивает шрифты из `public/` (лицензионные Gilroy / Proxima Nova, если их положили) —
   у них абсолютные URL, которые Vite специально не трогает, см. `FONTS.md`.
4. **Вырезает `@font-face`, который всё ещё указывает на отсутствующий файл.** Иначе он
   выстрелит запросом, CSP его убьёт, и в консоли страницы, которую никто не может
   отладить, появится ошибка. Вырезанное правило = семейство просто падает на следующее в
   стеке.
5. Отдаёт только содержимое страницы: хост артефакта сам даёт
   `<!doctype>/<html>/<head>/<body>`. `class="dark"` с `<html>` из `index.html`
   переставляется скриптом вручную.

Артефакт прототипа — постоянная ссылка, обновлять при каждом значимом изменении:
https://claude.ai/code/artifact/3a24a501-7176-4bf4-8e99-cbb56b7ba1a9

Смежное следствие CSP-песочницы: внутри неё могут быть закрыты `history`, `localStorage` и
`navigator.clipboard`. Поэтому все три вызова в коде — best-effort в `try/catch`
(`world.ts`, `ChatPanel.tsx`), и прототип продолжает работать без них.

## 15. Правило литеральных классов Tailwind

⚠️ **Имена классов в tsx всегда писать ПОЛНЫМИ ЛИТЕРАЛАМИ. Tailwind вычищает CSS-правила,
чьё имя класса он не встретил в исходниках дословно.** Контент-сканер не исполняет код,
поэтому строка, собранная динамически, для него не существует.

Этот урок укусил **дважды**:

1. `siri-layer--${k}` в `SiriGlow.tsx` — из сборки вычистило слои свечения, эффект
   пропал целиком. Сейчас там объект `LAYER_CLASS` с полными строками.
2. Тона скроллбара в `ScrollArea.tsx` — правила лежат внутри Tailwind-`@layer`, а Tailwind
   тряхнёт и правила слоя, если не нашёл имя класса дословно. Сейчас там `THUMB_CLASS` с
   полными строками.

Оба места помечены комментариями в коде. Любая новая пара «CSS-класс в `index.css` +
выбор класса в tsx» обязана строиться так же: полный литерал в маппинге, а не конкатенация.
