# Живой редактор DreamHost — что он делает сегодня (22.09.2026)

**Источник:** две экранные записи дизайнера (24 с и 32 с, 3504×1836) с
`panel.dreamhost.com/ai-editor/?domain=8d2c4c50a1fd16ee.remixer.ai`, его словами — «вот как
сейчас выглядит и работает». Кадры: `prototype/scratchpad/live-editor/keep/` (a-* — первая
запись, b-* — вторая), контактные листы `a-sheet.jpg` / `b-sheet.jpg`.

> Сеть облачной сессии режет `panel.dreamhost.com` (403 на CONNECT), и логина под аккаунтом у
> Claude нет — запись остаётся единственным способом увидеть продукт. Третий раз подряд она же
> оказывается точнее любого пересказа (ср. разбор Lovable 06.09.2026).

## 1. Шелл живого продукта ≠ шелл нашего прототипа

| | живой продукт | наш прототип (борд 25819:143144) |
|---|---|---|
| рейл с модулями | **СЛЕВА**, шириной ~48 | СПРАВА, 56 |
| чат | не виден (свёрнут; тумблер в правом конце топбара) | колонка 432 слева |
| топбар | `Visual Editor` · reload · девайс — СЛЕВА; адрес по ЦЕНТРУ с шевроном; `Publish` справа | те же элементы, другая раскладка |
| адрес | `8d2c4c50a1fd16ee.remixer.ai` — 16 hex | читаемое `fit-ration.remixer.ai` |
| канвас | сайт во всю ширину, скруглённый инсет | то же |

Рейл живого продукта сверху вниз: марка Remixer · картинки · пазл · **облако** · график ·
чат-иконка с плашкой **Beta**; внизу зелёный freshchat и аватар. То есть модулей уже шесть.

⚠️ Это НЕ расхождение с бордом, а разные эпохи: борд 2026 переносит рейл вправо. Но сам факт
надо помнить, когда дизайнер сравнивает прототип с тем, что открыто у него в панели.

## 2. Окно Cloud вживую

Структура совпадает с бордом `30816:49569`: меню слева, таблица справа, ✕ в правом верхнем углу,
выбранная таблица подсвечена фиолетовым. Чего на борде НЕТ, а в продукте есть:

- **Таблиц много, и это список клиента**, а не две штуки: Meal Plan · Dish · Ingredient · Client
  Subscription · Delivery Task · Client Menu Item · Payment · Role Assignment и ещё несколько с
  мусорными именами (`GRGRGRGRGRG`, `YUYUUYUY`, `RTRTRT`) — то есть список скроллится.
- **Кнопка называется `Add Table`**, а не `Add database` (борд). И у ряда таблицы есть меню «⋮».
- **Шестая комната — `Logs`** (борд рисует Emails · Secrets · Users · Storage).
- **`Add an Object`** — с большой O.
- **Скелетон загрузки**: серые плашки в ячейках, пока таблица едет.

### Переход сайт ⇄ Cloud вживую — покадрово (52 fps, `prototype/scratchpad/live-editor/tr-*`)

Заказ дизайнера 22.09.2026: «посмотри детально… как переключается окно с превью сайта на Cloud окно
и наоборот… в целом выглядит норм, но… сделай намного прикольнее, плавнее и более стильно… в Apple
liquid glass стиле… не навязчиво, не бьёт по глазам». Четыре момента в двух записях
(A: 1,0–1,5 с и 4,2–4,7 с; B: 31,7–32,2 с), вырезаны на полной частоте, бокс белой карточки сайта
замерен по кадрам (`sheet-a1/a2/a3/b1.jpg`).

**Открытие (сайт → Cloud) — вертикальная карусель:**

| такт | что происходит | длительность |
|---|---|---|
| 1 | карточка сайта **сжимается до ~92 %** (1198 из 1305 px ширины канваса на кадре 1400) и замирает | ~100 мс + пауза ~70 мс |
| 2 | сайт **уезжает ВВЕРХ с ускорением**: верх карточки 97 → 125 → 178 → 256 → 359 px за кадр | 4–5 кадров, **70–80 мс** |
| 3 | окно Cloud **въезжает снизу** тем же движением (одна лента) | те же кадры |
| 4 | окно **дорастает 92 → 100 %** с торможением | ~250 мс |

Итого ~500 мс. **Закрытие зеркально:** Cloud сжимается и уходит ВНИЗ, сайт **опускается сверху с
торможением** (верх 307 → 248 → 204 → 169 → 143 → 123 → 107 → 96 → 89 → 84 → 82 за ~180 мс), затем
дорастает (1198 → 1330 px за ~200 мс, ease-out). ~420 мс.

**Почему это «норм», а не «вау»:** лента — жёсткий слайд без пружины (уход за 4 кадра читается как
рывок); два движения — слайд и дорастание — видны по отдельности, как два шага; и ничто не связывает
окно с кнопкой, которая его вызвала (окно приезжает снизу, кнопка стоит слева на рейле). Материала в
переходе нет: ни кромки, ни света, ни глубины.

**Что взято в прототип и что заменено** — `docs/knowledge/design-system.md` §7 «Окно разворачивается из
своей кнопки». Коротко: вместо ленты — глубина (сайт отступает под приходящее окно), вместо слайда —
клип-морф из плитки кнопки в окно (одна форма r16 в двух размерах), вместо двух шагов — одна пружина.

### Экраны, которых на борде нет вообще

1. **Add Database** — отдельный полноэкранный лист внутри окна: имя базы, ряды параметров
   («Enter name» + тип `Text ▾` + корзина), `Add parameter +`, внизу `Cancel` и **синяя** `Create`.
   ⚠️ Синяя, а не фиолетовая — то есть акцент действия в живом продукте по-прежнему наш `--action`,
   а фиолетовый принадлежит модулю Cloud.
2. **Create Record / Edit Record** — правый ШИТ внутри окна (не модалка): поля по колонкам,
   `True/False`-переключатели для булевых, внизу `Cancel` + синяя `Create` / `Save`.
3. **Filters** — такой же правый шит: на каждую колонку `Include/Exclude` и значение, внизу
   `Close` + `Clear Filters`. Это то, что открывает кнопка-воронка.
4. **Delete record** — диалог: «Delete record · This will permanently remove this record from the
   database.» + `Cancel` / красная `Delete`.
5. **Delete {таблица} database?** — диалог с ЧИСЛОМ записей и последствием: «Ingredient. This
   permanently deletes the table and 3 records. Anything on your site that reads this table will
   stop working.» Это лучший кусок копирайта во всём живом окне: он называет, что сломается.
6. **Email** — комната собрана: слева `Inbox` («Form submissions arrive here») с адресом и
   предупреждением, справа `Sender` с замком `Locked`, иллюстрацией глобуса, «Connect a custom
   domain» и фиолетовой `Connect a domain`. В шапке — `No domain connected` и плашка `Blocked`.
7. **Users** — `Sign-in`, график и таблица `People`.

## 3. Что из этого стоит поднять дизайнеру

- `Add Table` против `Add database` и `Add an Object` против `Add an object` — борд и продукт
  расходятся в словах; прототип пока следует борду.
- `Logs` в меню нет на борде.
- Действия ряда в живом продукте стоят на КАЖДОМ ряду без растушёвки, борд рисует растушёвку.
- Диалоги удаления, правый шит записи и фильтры — готовый, уже написанный продуктом копирайт;
  если эти экраны будут рисоваться, начинать стоит с него, а не с чистого листа.
- Адрес стейджинга в живом продукте — 16 hex-символов, а прототип печатает читаемое имя.
