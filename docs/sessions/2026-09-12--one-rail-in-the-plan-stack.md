## 2. «У тебя тут двойные бордеры снова»

### 2.1. Диагноз: «убрать паддинг» ≠ «вытянуть ребёнка»

Это та же болезнь, что была у карточки генерации 09.09, и лекарство уже записано в
`CLAUDE.md`. Но записано оно ДВУМЯ вариантами — «вытянуть ребёнка на пиксель» или «снять рамку
с родителя», — и 11.09 я применил третий, которого в списке нет: **снял паддинг**.

Разница тонкая и решает всё. Строук Figma сидит ВНУТРИ геометрии, поэтому экспорт блока
страницы пишет `px-px pb-px` — это и есть обводка, а не отступ. Снятый паддинг даёт ПРАВИЛЬНЫЕ
координаты детям (шапка 796 на x=2 — замер сходится в ноль), и именно поэтому проверка их
пропустила. Но сам строук ребёнка при этом остаётся стоять РЯДОМ со строуком карточки, а не
НА нём.

Замер поперёк левой кромки (устройственные пиксели, dpr 2; земля карточки 26, строук 55):

| | было | стало |
|---|---|---|
| внутри блока страницы | `27 27 27 27 · **55 55 55 55** · 48 48` | `27 27 27 27 · **55 55** · 36 36 · 48 48` |
| запечатанный ряд | `**55 55 55 55**` | `**55 55**` |
| ниже последнего ряда | `55 55` | `55 55` |

То есть рельс был **2 CSS px** по всей высоте блока и по каждому запечатанному ряду, а там, где
к ним присоединялся волосок листа, — **3 CSS px** (карточка + блок + лист впритык). Свип по
всей кромке: было 359 строк с трёхпиксельным рельсом и 235 с двухпиксельным против 198
правильных; стало **768 строк ровно 1 CSS px из 813**, а оставшиеся 45 — антиалиасинг четырёх
углов и трёх касаний дуг (`524..531`, `633..638`, `729..734` — это и есть три шва).

**Что выбирает между лекарствами** — то же, что у карточки генерации: есть ли внутри дуги.
Дуга читается швом только потому, что за ней продолжается прямая линия; значит рельс должен
быть непрерывным, а тянуть надо ребёнка. Итог: `-mx-px -mt-px w-[calc(100%+2px)]` и
ВЕРНУВШИЙСЯ нарисованный `px-px pb-px`.

### 2.2. Шов снизу тоже общий

Плюс `-mb-px` на блоке страницы. На борде его нижний строук И ЕСТЬ верхняя кромка первой
ожидающей страницы: её фрейм начинается на y=275 — последнем пикселе собственных 275 блока.
Без этого карточка выходила на пиксель выше борда. С ним: **421 против 421** (1 + 275 + 48·3 + 1).

## 3. Что вскрылось заодно: «Add a section» стоял не в своей колонке

Раз уж борд был открыт, сверил колонки по `get_metadata`, а не по рендеру. Борд даёт ряду
«Add a section» свой ПУСТОЙ фрейм локтя (x=0, w=16) — поэтому его диск попадает в колонку
иконок секций (**x=36**), лейбл под их имена (**x=72**), а воздуха над ним **16**, а не 8
(Step 8 — это фрейм 32 с иконкой на y=8 поверх собственного шага списка 8).

Было: диск x=20, лейбл x=56, воздух 8 — ряд висел на паддинге листа, в колонке, в которой не
стоит больше ничего. В рендере 1:1 это выглядит как «чуть левее», поэтому нашлось только в
метаданных.

Сверка после правки, всё против борда:

| | борд | стало |
|---|---|---|
| карточка | 800 × (1 + 275 + 48·n + 1) | 800 × 421 ✓ |
| шапка блока | x=2, 796 × 48 | ✓ |
| лист | x=2, 796 × 226 | ✓ |
| иконка секции / её имя | 36 / 72 | ✓ |
| диск и лейбл «Add a section» | 36 / 72, воздух 16 | ✓ |
| иконка ожидающей страницы / имя | 13 / 41 | ✓ |
| диск и лейбл «Add a page» | 12 / 44 | ✓ |
