# Журнал сессий — как его вести

> **Назначение:** глобальная память о том, кто что делал. Каждое окно Claude, которое
> когда-либо работало над Remixer, оставляет здесь одну запись — чтобы работа не терялась
> и не переделывалась заново.
> **Обновлено:** 25.08.2026

---

## Правила

1. **Одна сессия = один файл** в этой папке. Имя: **`YYYY-MM-DD--slug.md`**
   (дата начала сессии + короткий английский slug через двойной дефис).
   Примеры: `2026-08-16--prototype-shell-and-domains.md`, `2026-08-25--home-page-and-knowledge-base.md`.
2. **Запись создаётся В НАЧАЛЕ работы и дописывается по ходу** — не «в конце, если успею».
   Контейнер сессии умирает молча; недописанная запись = потерянная сессия.
3. **`index.md` обновляется вместе с записью** — строкой в самом верху таблицы.
4. **Ничего не переписываем задним числом.** Ошиблись — добавляем строку «поправка от …».
5. **Реконструкция помечается явно.** Если запись собрана из git-истории и документов, а не
   написана участником сессии, в шапке стоит `Статус: реконструкция`. Это честность:
   реконструкция может врать в деталях.

## Что обязана содержать запись

| Поле | Зачем |
|---|---|
| **Дата** | сортировка и связь с датами в `CLAUDE.md` |
| **Ветка** | без неё нельзя найти коммиты |
| **Статус** | `в работе` / `завершена` / `реконструкция` |
| **Роль/состав** | одна сессия или менеджер + параллельные агенты (и кто за что отвечал) |
| **Цель** | зачем сессию начали, в одном абзаце |
| **Что сделано** | по пунктам, с путями к файлам |
| **Что решено** | решения дизайнера — принятые И отклонённые; дублируются строкой в `knowledge/decisions.md` |
| **Что осталось** | незакрытые вопросы, чтобы следующая сессия начала не с нуля |
| **Коммиты** | хеши или тема+количество; если ветка не пушилась — сказать об этом |
| **Ссылки** | созданные/изменённые документы, артефакты, узлы Figma |

## Шаблон

```markdown
# YYYY-MM-DD — <тема>

> **Ветка:** claude/… · **Статус:** в работе | завершена | реконструкция
> **Состав:** …

## Цель
## Что сделано
## Что решено
## Что осталось
## Коммиты
## Ссылки
```

## Особенности этого репозитория

- **История git в рабочем клоне обрезана (grafted).** Видны только коммиты с 16.08.2026;
  всё, что раньше, восстанавливается по документам и датам внутри них. Поэтому у ранних
  сессий в записях стоит `Статус: реконструкция` и нет хешей.
- **Ветка per-session.** Каждая сессия работает в своей ветке `claude/remixer-*`;
  ветка указана в `CLAUDE.md` → «Рабочие соглашения» и должна там обновляться.
- Пушить после каждого законченного куска работы — иначе смерть контейнера уносит работу
  вместе с записью о ней.
