## 2. Модель страниц (`pages.ts`)

`sitePages(brief.answers, planEdits.outline)` → `buildOutline(...)`, тот же outline, что читают Build Plan,
карточка генерации и Autopilot. Первая страница — `/`, остальные — `/` + slug английского имени (`About` →
`/about`, `Item page` → `/item-page`). `normalizePath` приводит набранное к роуту (ведущий слэш, нижний
регистр, пробелы → дефисы); `findPage` ищет по нормализованному пути; `matchPages` фильтрует по имени
(обе локали) и слагу, ведущий слэш в запросе игнорируется.

## 4. Правила реализации

1. **Поле — `defaultValue`, не `value`.** Контролируемое поле, переписанное React после `select()`, теряет
   выделение (замер: `[6, 6]` на «/about» при повторном открытии). Текст пишется руками (`write`), `query`
   зеркалит DOM для фильтра. Пока стоит предзаполнение, у поля `data-prefill`, и `::selection` прозрачна
   (`index.css`) — выделение есть (набор заменяет роут), полосы нет, как на борде.
2. **Взвод при открытии ждёт `at`** (позицию пилюли из `useLayoutEffect`): поле существует только после
   размещения бокса; `armed` не даёт ресайзу перевзвести поле посреди ввода.
3. **Подсветка — состояние, не `:hover`.** Одна подсветка на мышь и клавиатуру.
4. **Портал в `<body>`**, `fixed`, `z-[60]`; позиция перемеряется на `resize`.
5. **Каждая страница превью — свой `ScrollArea`**, поэтому новая открывается с верха; короткая страница
   тянется `min-h-full`, футер прижат к низу.
6. **`data-*` для приёмки:** `data-page-switch`, `data-page-label`, `data-page-chevron`, `data-page-menu`,
   `data-page-field`, `data-page-input`, `data-page-row={path}`, `data-page-lead`, `data-page-text`, `data-active`, `data-current`,
   `data-page-goto`, `data-site-page={path}`, `data-site-link={path}`, `data-site-notfound`.
