## 0. Задача словами дизайнера

> Когда кастомер пишет плохой, неинформативный промпт, Remixer понимает, что промпт слабый, **не начинает
> генерацию**, а — как Lovable — переводит пользователя в чат по центру (превью схлопнуто) и задаёт
> дополнительные вопросы, чтобы собрать нормальный бриф. Только после ответов и плана начинается
> генерация. Визуально — 1 в 1 как у Lovable: логика, дизайн, вёрстка, анимации раскрытия превью и
> ресайза чата.

Эталон снят с реальной записи экрана дизайнера (06.09.2026): промпт «Build me a website.» →
центральный чат → четыре вопроса в панели над композером → сводка → «Got it — …» → билд.

**Уточнение Романа (07.09.2026, критерий приёмки):** на домашней странице основного прототипа
(https://claude.ai/code/artifact/3a24a501-7176-4bf4-8e99-cbb56b7ba1a9?hide-ui=1 — герой «Describe it.
Remixer builds it.», композер «e.g. Bella's Bakery», «+», «Add template», микрофон, «Build ↵», чипы
шаблонов) он вводит **любой промпт короче 10 символов** и нажимает Build. Вместо генерации открывается
билдер с **чатом по центру и схлопнутым превью**, Remixer задаёт вопросы как Lovable, собирает план и
только потом генерирует. Правило в коде: `isWeakPrompt()` = длина < 10 символов ИЛИ меньше двух слов
по существу (поэтому «Build me a website.» тоже слабый, а пример из плейсхолдера «Bella's Bakery» — нет).

### Схема состояний (как это работает)

```
project=empty, sent=[]  ──send(weak)──▶ chat=working (2.6 s)
                                              │
                                              ▼
                              clarify-msg («Thought for 3s» + BRIEF_INTRO)
                              brief.status=asking, step=0 ─── панель над композером
                                              │  Next / ‹ › / Skip all / Submit
                                              ▼
                              brief-card msg, brief.status=ready, chat=working (1.4 s)
                                              ▼
                              ack-msg («Got it — …»), project=generating,
                              ui.previewOpen=true  ── glow на превью (4.2 s)
                                              ▼
                              done-msg, project=built, credits−10, unpublished+1

project=empty ──send(strong)──▶ project=generating, previewOpen=true, chat=working (2.6 s) ──▶ built
Отправка из композера при открытой панели ──▶ brief=none, промпт обрабатывается как новый.
```

Превью: `ui.previewOpen`. Эффекты в `App.tsx`: «свежий» проект (empty + пустой транскрипт + chat empty) →
схлопнуто; `project === 'generating'` → раскрыто. Пользователь может переключать всегда.
Порог схлопывания при драге: канвас уже `PREVIEW_MIN` (480) + 24.

## 6. Ограничения окружения и уроки (сэкономят часы)

- **Сеть.** Окружение «Trusted» блокирует все сайты, кроме GitHub и реестров пакетов: lovable.dev,
  docs.lovable.dev, web.archive.org — 403 и для curl, и для Chromium, и для WebFetch. Работает WebSearch.
  Для живой проверки Lovable Роман должен переключить окружение на Network access → Full (кнопка-облако
  над полем ввода на claude.ai/code → шестерёнка) и дать тестовый аккаунт Lovable (email + пароль).
  Действует только на новые сессии.
- **Запись экрана лучше любых статей.** Роман умеет снимать .mov и загружать в чат. Системный ffmpeg
  Playwright не читает .mov; ставить `pip install imageio-ffmpeg` и брать бинарь из
  `/usr/local/lib/python3.11/dist-packages/imageio_ffmpeg/binaries/`. Дальше: контакт-листы (`fps=1,tile=6x4`),
  детекция сцен (`select='gt(scene,0.06)'`), затем точечные кадры и кропы колонки чата.
- **Не запускать тяжёлые многоагентные воркфлоу**: в этой сессии два воркфлоу (23 агента) исчерпали
  лимит аккаунта на середине; 17 агентов упали с «out of usage credits». Их результат частично спасён
  в разделе 3 разбора. Работать соло, читать целенаправленно.
- **Ловушки инструментов.** `pkill -f` по словам из своей же команды убивает собственный шелл (совпадение
  по строке команды; дважды за сессию) — фоновые серверы останавливать по PID (`$!`) или отдельной командой. Read-инструмент показывает картинки; крупные
  выводы уходят в файл — печатать частями (`head -c`).
- **Шрифты.** Gilroy/Proxima Nova в репозиторий не кладём (публичный репозиторий); подмены Outfit/Figtree
  зашиты. Смотри блок «Шрифты» в `CLAUDE.md`.
- **Артефакты.** Публикация без `url` создаёт новый артефакт; чтобы обновить существующий — сначала
  `action: read` с его URL. Wake-подписки на артефакты в этой сессии были недоступны (403) — не заявлять.

## 7. Инварианты — не ломать

- Сброс брифа в `world.set`: гасить только при СТАВКЕ ситуации (ось `chat` без транскрипта или с пустым),
  никогда — при живом append в `sent` (иначе сводка покажет «Remixer's pick» во всех строках; это уже
  было и починено).
- Панель вопросов — над композером, не в треде. Один вопрос за раз. Композер под ней живой.
- Контент чата центрируется классом `chat-col` (600); «чат по центру» — не отдельный режим.
- Свечение — единственный индикатор загрузки превью; поэтому превью раскрывается при `generating`.
- Все правила `CLAUDE.md` про перф (transform/opacity, Tailwind чистит динамические классы, reduced-motion).
- Facts-дисциплина: у каждого факта о Lovable — статус и дата; в разборе статусы проставлены.
