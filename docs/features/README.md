## Шаблон фича-README

```markdown
# <Фича>

> Назначение · Обновлено: дд.мм.гггг
> Figma: узлы <id> (снято дд.мм.гггг), файл <ссылка>
> Код: prototype/src/…

## 1. Что это и зачем        — одна-две абзаца, для человека, который видит фичу впервые
## 2. Анатомия / геометрия   — размеры, токены, из какого узла Figma взято
## 3. Состояния              — полный список, включая пустое и ошибочное
## 4. Решения                — короткие строки + ссылка на knowledge/decisions.md
## 5. Где код                — файл : что в нём лежит
## 6. Открытые вопросы       — что не нарисовано, что спрошено у дизайнера и не отвечено
## 7. Ссылки                 — спека / QA / хендофф / ресёрч
```

## Правила для фича-баз

1. **Номер узла Figma и дата снятия — в первой строке.** Через месяц макет уедет, и без
   номера нельзя доказать, что было нарисовано.
2. **Состояния перечислять полностью, включая те, которых нет в макете.** Отсутствие
   состояния — самая ценная находка (пример: в доменном поиске **не нарисован** «домен
   занят»).
3. **Жёсткие ⚠️-уроки живут в `CLAUDE.md`**, здесь — их разъяснение и ссылка на код.
   Не наоборот: `CLAUDE.md` читают всегда, фича-README — по ссылке.
4. **Решения дублируются одной строкой в `knowledge/decisions.md`** — чтобы «уже
   отклонённое» находилось одним поиском по одному файлу.
